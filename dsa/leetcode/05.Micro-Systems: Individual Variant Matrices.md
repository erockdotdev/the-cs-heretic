## Family 1 — Linear Array Optimization

### Frame (Sliding Window)a
| Variant                   | Core Constraint                        | Key Assumption                      | Failure Trigger                  |
| ------------------------- | -------------------------------------- | ----------------------------------- | -------------------------------- |
| Fixed-size                | Window length = k                      | Adding/removing one element is O(1) | Need variable constraint         |
| Variable-size (At most K) | Expand right, shrink left when invalid | Non-negative or monotonic effect    | Negatives / loss of monotonicity |
| Variable-size (Exactly K) | Same as above + count valid windows    | Same as above                       | Same as above                    |
| 2-D Collapse              | Treat each row as an "element"         | Can reduce matrix to 1-D sequence   | True 2-D topology required       |

### Ledger (Prefix Sum + Hash Map)
| Variant              | Payload                    | Typical Query                             | Strength             |
| -------------------- | -------------------------- | ----------------------------------------- | -------------------- |
| Sum → Count          | `Map<Sum, Count>`          | Number of subarrays with sum = k          | Works with negatives |
| Value → Index        | `Map<Value, Index>`        | "Have I seen this before?"                | Position recovery    |
| Sum → Earliest Index | `Map<Sum, Earliest Index>` | Longest/shortest subarray with sum = k    | Span length          |
| Frequency only       | `Map<Value, Freq>`         | Count of distinct / frequency constraints | No prefix needed     |

### Vise (Two Pointers)
| Variant          | Movement Pattern  | Requires Sorted? | Classic Use                                      |
| ---------------- | ----------------- | ---------------- | ------------------------------------------------ |
| Converging       | Left ↑ + Right ↓  | Yes              | Pair / triplet sum, container with most water    |
| Same-directional | Both left → right | No               | Remove duplicates, partition                     |
| Fast & Slow      | Different speeds  | No               | Cycle detection, middle of list, in-place filter |
| Three Pointers   | Dutch-flag style  | No               | Sort colors / 3-way partition                    |

## Family 2 — Sorted Search & Range Compression

### Pivot / Binary Search
| Variant                 | Search Space        | Key Invariant            | Extra Step                  |
| ----------------------- | ------------------- | ------------------------ | --------------------------- |
| Classic Target          | Sorted array        | `lo ≤ target ≤ hi`       | None                        |
| Lower / Upper Bound     | Sorted array        | First/last position      | Careful `mid` & boundary    |
| Rotated Array           | Rotated sorted      | Find pivot first         | Two binary searches         |
| Binary Search on Answer | Answer range itself | Feasibility is monotonic | `isFeasible(mid)` check     |
| Real-valued             | Continuous range    | Same as above            | Fixed iterations or epsilon |

### Sweep Line / Interval Collapse
| Variant          | Event Type           | Active State                  | Classic Problem               |
| ---------------- | -------------------- | ----------------------------- | ----------------------------- |
| Merge Intervals  | Start / End          | Current merged interval       | Merge overlapping intervals   |
| Coverage Count   | Start / End          | Active interval counter       | Meeting rooms, range coverage |
| Skyline          | Building start / end | Active heights (often + heap) | Skyline problem               |
| Difference Array | Range update         | Prefix sum after updates      | Range add + point query       |

## Family 3 — Hierarchical & Network State

### DFS
| Variant             | Structure             | Extra State            | Use Case                           |
| ------------------- | --------------------- | ---------------------- | ---------------------------------- |
| Tree DFS            | Acyclic               | Parent only            | Path sum, diameter, LCA prep       |
| Graph DFS + Visited | May have cycles       | Visited set            | Connectivity, cycle detection      |
| 3-Coloring DFS      | Directed / undirected | White/Gray/Black       | Cycle detection in directed graphs |
| Path-Recording DFS  | Any                   | Path array + backtrack | All paths, root-to-leaf            |
| Topological (DFS)   | DAG                   | Finishing times        | Course schedule, dependency order  |

### BFS
| Variant          | Structure    | Extra State                       | Use Case                           |
| ---------------- | ------------ | --------------------------------- | ---------------------------------- |
| Classic BFS      | Unweighted   | Dist / visited                    | Shortest path                      |
| Multi-source BFS | Grid / Graph | Queue seeded with multiple starts | Rotting oranges, walls & gates     |
| Level-order      | Tree         | Level size tracking               | Binary tree level averages         |
| Kahn's Algorithm | DAG          | Indegree + queue                  | Topological sort (preferred in JS) |

### Union-Find
| Variant          | Optimization          | Extra Data        | Strength                      |
| ---------------- | --------------------- | ----------------- | ----------------------------- |
| Basic            | None                  | Parent array only | Simple connectivity           |
| Path Compression | Recursive / iterative | Parent only       | Flatten trees                 |
| Union by Rank    | Rank array            | Rank              | Keep trees balanced           |
| Union by Size    | Size array            | Size              | Same + component size queries |
| With Edge Count  | Size + edges          | Both              | Detect cycles while merging   |

### State Tracker

## Family 4 — Dynamic Priority & Streaming

### Binary Heap
| Variant              | Behavior                 | Extra Technique            | Classic Use                 |
| -------------------- | ------------------------ | -------------------------- | --------------------------- |
| Min-Heap             | Extract-min              | None                       | Dijkstra, Prim              |
| Max-Heap             | Extract-max              | None                       | Top-K largest               |
| Size-bounded (Top-K) | Keep only k elements     | Evict when size > k        | Top-K frequent              |
| Lazy Deletion        | Support arbitrary remove | Frequency map + skip stale | Sliding window median, etc. |

### Monotonic Deque
| Variant          | Order Maintained      | Stores  | Classic Use              |
| ---------------- | --------------------- | ------- | ------------------------ |
| Decreasing       | Values non-increasing | Indices | Sliding Window Maximum   |
| Increasing       | Values non-decreasing | Indices | Sliding Window Minimum   |
| Next Greater     | Decreasing            | Indices | Next Greater Element     |
| Previous Smaller | Increasing            | Indices | Previous Smaller Element |

### Trie
| Variant            | Compression      | Children           | Classic Use                            |
| ------------------ | ---------------- | ------------------ | -------------------------------------- |
| Standard           | None             | `Map` or array[26] | Autocomplete, prefix count             |
| Compressed / Radix | Path compression | Fewer nodes        | Memory-sensitive string sets           |
| Board-walking      | None             | `Map`              | Word Search II (used with DFS on grid) |

### Order-Statistic Upgrade
| Variant      | Query Power               | Implementation Cost | When to reach for it                 |
| ------------ | ------------------------- | ------------------- | ------------------------------------ |
| Fenwick Tree | Prefix sums / rank        | Low–Medium          | Many range sum updates               |
| Segment Tree | Arbitrary range + update  | Medium              | Range min/max + updates              |
| Balanced BST | Order statistics + delete | High                | Need full sorted order under updates |

**Upgrade path:** Fenwick Tree → Segment Tree → Balanced BST, in order of increasing power and implementation cost — reach for the cheapest one that satisfies the query pattern.

## Family 5 — Exhaustive State-Space & Optimization

### Greedy
| Variant               | Choice Rule                    | Proof Style        | Classic Examples                         |
| --------------------- | ------------------------------ | ------------------ | ---------------------------------------- |
| Sort + One Pass       | Sort then scan                 | Exchange argument  | Activity selection, jump game II         |
| Priority-Queue Greedy | Always take current best       | Matroid / exchange | Huffman, minimum cost to connect         |
| Interval Greedy       | Earliest finish / latest start | Exchange           | Meeting rooms, non-overlapping intervals |
| Fractional Knapsack   | Value density                  | Exchange           | Fractional knapsack                      |

### Backtracking
| Variant                 | Generation Style                 | Pruning          | Classic Use                    |
| ----------------------- | -------------------------------- | ---------------- | ------------------------------ |
| Subsets / Combinations  | Include / exclude or start index | Skip duplicates  | Subsets, combination sum       |
| Permutations            | Swap or used[] array             | Skip used        | Permutations, next permutation |
| Constraint Satisfaction | Place + check                    | Early conflict   | N-Queens, Sudoku, Word Search  |
| Path Finding            | Build path + restore             | Visited + bounds | All paths in graph, maze       |

### Dynamic Programming
| Variant                | Direction  | State Shape                 | Classic Family                           |
| ---------------------- | ---------- | --------------------------- | ---------------------------------------- |
| Top-down (Memo)        | Recursive  | Any                         | General overlapping subproblems          |
| Bottom-up (Tabulation) | Iterative  | Array / Matrix              | Classic knapsack, LIS                    |
| 0/1 Knapsack           | Either     | `dp[i][w]` or optimized     | Subset sum, target sum                   |
| Unbounded Knapsack     | Either     | `dp[w]`                     | Coin change                              |
| LIS / LCS style        | Either     | `dp[i]` or `dp[i][j]`       | Longest increasing / common subsequence  |
| Bitmask DP             | Either     | `dp[mask]` or `dp[mask][i]` | TSP, subset DP (`n ≤ 20`)                |
| Interval DP            | Bottom-up  | `dp[l][r]`                  | Matrix chain, burst balloons             |
| Tree DP                | DFS + memo | `dp[node][state]`           | Tree diameter variants, house robber III |
| Digit DP               | Top-down   | `dp[pos][tight][...]`       | Count numbers with property              |

## Cross-Cutting Micro-Systems

### Monotonicity Exploitation
| Variant                      | Domain                  | Enables                     |
| ---------------------------- | ----------------------- | --------------------------- |
| Sequence monotonicity        | Array values            | Two pointers, binary search |
| Window validity monotonicity | Sliding window          | Safe expand/shrink          |
| Feasibility monotonicity     | Binary Search on Answer | Correct `lo`/`hi` movement  |
| Choice monotonicity          | Greedy                  | Local → global proof        |

### State Design (Family 5 core skill)
| Quality                | Definition                                       | Test                               |
| ---------------------- | ------------------------------------------------ | ---------------------------------- |
| Minimal                | Smallest tuple that still decides optimally      | Can any dimension be removed?      |
| Collision-guaranteeing | Overlapping subproblems share the exact same key | Same state → same future decisions |
| Reconstructible        | Optional parent/choice pointers                  | Needed only when path is required  |
