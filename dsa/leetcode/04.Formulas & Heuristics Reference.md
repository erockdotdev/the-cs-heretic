## 1. Core Complexity & Economic Formulas

| Concept                         | Formula / Relation                                                           | Meaning                                 |
| ------------------------------- | ---------------------------------------------------------------------------- | --------------------------------------- |
| Time–Space Trade-off            | $T_{\text{new}} \approx T_{\text{old}} / S_{\text{extra}}$ (idealized)       | Paying space tax to reduce time         |
| Nested-loop Amnesia             | $O(n^2)$ or $O(n\cdot k)$ when state is not persisted                        | Classic symptom of Algorithmic Amnesia  |
| Sliding Window (amortized)      | $O(n)$ total — each element enters and leaves the window at most once        | Frame success condition                 |
| Prefix + Map                    | Preprocess $O(n)$, query $O(1)$                                              | Ledger strength                         |
| Binary Search                   | $O(\log n)$ per search, $O(n\log n)$ if sorting first                        | Pivot family                            |
| Binary Search on Answer         | $O(\log(\text{answer range}) \cdot C)$ where $C$ = cost of feasibility check | Most common Family 2 pattern            |
| BFS / DFS                       | $O(V + E)$                                                                   | Family 3 baseline                       |
| Binary Heap operations          | Insert / Extract-min = $O(\log n)$                                           | Family 4                                |
| Monotonic Deque (window)        | $O(n)$ total — each index pushed and popped at most once                     | Preferred over heap for window extremes |
| Union-Find (with optimizations) | Nearly $O(\alpha(n))$ ≈ constant per operation                               | Path compression + union by rank/size   |
| DP State Count                  | Number of states × transition cost                                           | Must stay within time limit             |
| Bitmask DP                      | $O(2^n \cdot n)$ or $O(2^n \cdot n^2)$                                       | Feasible only for $n \leq 20$–22        |
| Backtracking upper bound        | $O(b^d)$ where $b$ = branching factor, $d$ = depth                           | Must prune aggressively                 |

## 2. The Canonical N-Scale / Constraint Budget Table

This is the single source of truth for "given N, what complexity is legal, and which family/tool should I reach for." Every other Core doc should reference this table by name rather than restate it.

**Basis:** JS/V8 clears roughly $10^8$ simple operations per second. Each row below is checked against that ceiling using the *resolved* operation count, not just the raw N.

| N Scale       | Resolves To  | Acceptable Complexity         | Family / Tool                                                                                                                        | Note                                                                                                                       |
| ------------- | ------------ | ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| $\leq 20$     | ~20 items    | $O(2^n \cdot \text{poly}(n))$ | **Family 5 — Exhaustive State-Space & Optimization** (Backtracking, Bitmask DP)                                                      | $2^{20} \approx 1M$ — fast even with a polynomial multiplier                                                               |
| $\leq 10^3$   | 1,000        | $O(n^2)$                      | **Family 5** (2-D DP) / **Family 3 — Hierarchical & Network State** (dense graphs)                                                   | $1{,}000^2 = 1M$ ops — comfortable, far under budget                                                                       |
| $10^3$–$10^4$ | 1,000–10,000 | $O(n^2)$, borderline          | Most families viable — but start hunting for $O(n\log n)$                                                                            | $10{,}000^2 = 100M$ ops — right at the ceiling; real per-op overhead often tips this into TLE                              |
| $\leq 10^5$   | 100,000      | $O(n\log n)$                  | **Family 2 — Sorted Search & Range Compression**, **Family 4 — Dynamic Priority & Streaming**, most of **Family 1** and **Family 3** | $100{,}000 \times \log_2(100{,}000) \approx 1.7M$ ops — comfortable                                                        |
| $\leq 10^6$   | 1,000,000    | $O(n)$, strict linear         | **Family 1 — Linear Array Optimization**, standard BFS/DFS in **Family 3**                                                           | Time is trivial here; the real constraint is usually memory — prefer TypedArrays over `Map` when the value domain is small |
| $\geq 10^9$   | 1 billion+   | $O(\log n)$ or $O(1)$         | **Family 2** — pure math / Binary Search on Answer                                                                                   | Even $O(n)$ (1B ops) is too slow — this tier is a signal you need a formula, not an iteration                              |

**Known gap (by design, not oversight):** there's no explicit tier between $10^6$ and $10^9$. In practice $O(n)$ still holds up to roughly $10^8$ before sub-linear becomes necessary — so $n \approx 10^7$–$10^8$ is still "Family 1, linear" territory. LeetCode-style constraints rarely land exactly in this gap, so it's left implicit rather than given its own row — but don't let the table mislead you if you hit it.

**V8 Reality**
Roughly $10^8$ simple operations per second. Allocation and GC are first-class costs. Hidden classes / shape monomorphism affect property access speed. Call stack is finite and relatively small (~10k–15k frames).

## 3. Family 1 Formulas & Heuristics

#### Sliding Window (Frame)
- **Amortized cost**: each of the $n$ elements is added and removed at most once → $O(n)$.
- **Validity heuristic**: if adding an element can only make the window "worse" or "better" monotonically, variable window is safe. Negatives or non-monotonic updates → abandon Frame.

#### Prefix Sum
- Classic: $\text{prefix}[i] = \text{prefix}[i-1] + \text{nums}[i]$
- Range sum $[L..R] = \text{prefix}[R] - \text{prefix}[L-1]$
- Subarray sum = $k$ count: $\text{ans} \mathrel{+}= \text{map}[\text{currentSum} - k]$

#### Two Pointers (Vise)
- **Converging heuristic**: on sorted array, if $\text{sum} < target$ move left pointer right; if $\text{sum} > target$ move right pointer left.
- **Invariant**: at every step the pair (or triplet) under consideration is the only candidate that can still satisfy the condition given previous decisions.

**Decision Heuristic (Family 1)**
```
Need contiguous segment? → Frame
Has negatives / need arbitrary range? → Ledger
Data sorted + pair/partition? → Vise
Need original indices after sort? → pay space tax, stay with Ledger
```

## 4. Family 2 Formulas & Heuristics

#### Binary Search
- Mid calculation (overflow-safe): $\text{mid} = \text{lo} + \lfloor(\text{hi} - \text{lo}) / 2\rfloor$, or bit form: $\text{mid} = \text{lo} + ((\text{hi} - \text{lo}) \gg 1)$
- Loop invariant forms: $lo < hi$ (preferred for lower-bound style) vs. $lo \le hi$ (classic target search)

#### Binary Search on Answer
- Feasibility must be monotonic: if $x$ is feasible then every $y > x$ (or $< x$) is also feasible.
- Answer range size determines iterations: $\lceil\log_2(\text{hi}-\text{lo}+1)\rceil$

#### Sweep Line
- Event sorting key: Primary = position, Secondary = type (starts before ends, or negative height trick for skyline).
- Active count updates: $+1$ on start, $-1$ on end.

**Decision Heuristic (Family 2)**
```
Strictly sorted + exact target/bound → Classic Binary Search
Rotated → Find pivot, then Binary Search in correct half
Answer itself is monotonic → Binary Search on Answer
Overlapping intervals / coverage → Sort endpoints → Sweep Line
```

## 5. Family 3 Formulas & Heuristics

#### Graph Traversal
- Time: $O(V + E)$. Space: $O(V)$ for visited / parent / dist.

#### Union-Find
- With path compression + union by rank: amortized time per operation $= O(\alpha(n))$ where $\alpha$ is the inverse Ackermann function (effectively ≤ 4 for all practical $n$).

#### Shortest Path (unweighted)
- BFS distance: $\text{dist}[v] = \text{dist}[u] + 1$ when first reaching $v$.

**Decision Heuristic (Family 3)**
```
Pure tree (no cycles) → DFS or BFS, parent tracking enough
Unweighted shortest path → BFS + visited
Components / cycles → DFS + coloring or Union-Find
Many merges → Union-Find
Need distances or path reconstruction → BFS/DFS + maps
Weighted edges → exit to Family 4 (Dijkstra)
```

## 6. Family 4 Formulas & Heuristics

#### Binary Heap
- Height $= \lfloor\log_2 n\rfloor$. Insert / Extract = $O(\log n)$. Build heap = $O(n)$.

#### Monotonic Deque
- Each index pushed and popped at most once → $O(n)$ total for sliding window extremes.

#### Dijkstra (embedding)
- With binary heap: $O((V + E)\log V)$. With Fibonacci heap (theoretical): $O(E + V\log V)$.

**Decision Heuristic (Family 4)**
```
Need continuous min/max or Top-K → Binary Heap
Sliding window max/min → Monotonic Deque (usually better)
Arbitrary deletions → Lazy deletion (freq map + delayed pop)
Heavy prefix sharing on strings → Trie
Need full order statistics repeatedly → upgrade to Fenwick / Segment Tree / Balanced BST
```

## 7. Family 5 Formulas & Heuristics

#### Greedy
- **Exchange argument heuristic**: show that any optimal solution can be transformed into the greedy solution without increasing cost by swapping choices.
- **Matroid heuristic**: if the structure is a matroid, greedy is optimal.

#### Backtracking
- Time bound: $O(b^d)$. Pruning reduces effective branching factor.

#### Dynamic Programming
- **Optimal Substructure**: optimal solution of the problem contains optimal solutions of subproblems.
- **Overlapping Subproblems**: the same subproblem appears multiple times.
- Number of states must be polynomial (or $2^n$ with $n\leq 20$).
- Transition: $\text{dp}[s] = \text{opt over previous states } s'$ of $f(\text{dp}[s'], \text{choice})$

**State Design Heuristic**
```
Start with the full set of information needed to make the next decision.
Remove any dimension that does not affect future choices or correctness.
Verify that two different paths reaching the same state have identical future options.
```

**Decision Heuristic (Family 5)**
```
Can I prove a greedy choice property? → Greedy
No, and n is small or all solutions needed → Backtracking
Overlapping subproblems + optimal substructure → DP
n ≤ 20 and subsets matter → Bitmask DP
```

## 8. Cross-Family & General Heuristics

| Heuristic               | Statement                                                                                                    |
| ----------------------- | ------------------------------------------------------------------------------------------------------------ |
| Topology First          | Always identify physical topology before choosing any technique.                                             |
| Assumption Check        | Never apply a technique whose key assumption is violated (monotonicity, sortedness, no negatives, etc.).     |
| Space Tax Awareness     | When a technique discards information you later need, you must pay memory to recover it.                     |
| Embedding Preference    | Family 4 tools are most often *embedded* inside Families 1–3 rather than being the primary topology.         |
| Dimensional Collapse    | Try to reduce 2-D to 1-D before treating a matrix as a full graph or DP table.                               |
| Silent Failure Warning  | Greedy and some window techniques can produce wrong answers without crashing — always seek counter-examples. |
| Interview Verbalization | In the first 60–90 s state: topology → starting family → first tool → why it may fail → next tool or exit.   |

## 9. JS/TS-Specific Heuristics & Formulas

| Heuristic / Formula   | Detail                                                                                                                         |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Hidden Quadratic      | Any `.slice`, `.splice`, spread, or `.filter().map()` inside a loop turns $O(n)$ into $O(n^2)$.                                |
| Map Access            | Prefer `map.get(x) ?? 0` after `.has(x)` when 0 is a valid value.                                                              |
| Sort Comparator       | Always `(a, b) => a - b` for numeric order.                                                                                    |
| Recursion Limit       | Practical call-stack ≈ 10k–15k frames. Beyond that convert to iterative.                                                       |
| TypedArray Preference | When value domain is small and $n \ge 10^6$, `Int32Array` / `Uint8Array` beats `Map` for frequency counting.                   |
| Amortized Window      | Monotonic deque or sliding window with two pointers stays $O(n)$ only if each element is processed a constant number of times. |
| Bitmask Size          | $2^{20} = 1{,}048{,}576$, $2^{22} \approx 4M$ — practical upper limits for Bitmask DP in JS.                                   |

## 10. Quick Formula Cheat Sheet (Most Used)

```
Range sum [L..R]           = prefix[R] - prefix[L-1]
Binary mid                 = lo + ((hi - lo) >> 1)
BFS / DFS time              = O(V + E)
Heap insert/extract         = O(log n)
Monotonic deque window      = O(n)
Union-Find (optimized)      = O(α(n)) ≈ O(1)
Bitmask DP                  = O(2^n · poly(n))
Sliding window amortized    = O(n)
Binary Search on Answer     = O(log(range) · feasibility)
```
