## 1. Foundational Concepts (Root Layer)

These are the primitive ideas that everything else is built on.

| Concept                      | Definition                                                                                                                                         | Role in the System                                                                     | Key Implications                                                                                                                                |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| **Physical Topology**        | The inherent structural shape of the input data (contiguous line, ordered ranges, nodes+edges, mutable stream, or combinatorial decision space).   | Primary routing key for choosing a Super-Family.                                       | Determines which family of tools is even applicable before any algorithm is chosen.                                                             |
| **State Persistence**        | The deliberate storage of previously computed information so it does not have to be recomputed.                                                    | Core economic principle: trade memory for time.                                        | The opposite of Algorithmic Amnesia. Almost every efficient solution in Families 1–4 relies on some form of it.                                 |
| **Algorithmic Amnesia**      | The failure mode in which an algorithm recomputes the same information repeatedly because it retains no memory of prior work.                      | Primary diagnosis of brute-force nested loops.                                         | Classic symptom: $O(n^2)$ or worse solutions that "feel" simple.                                                                                |
| **Computational Redundancy** | Performing work that could have been avoided by exploiting structure (order, monotonicity, overlapping subproblems, etc.).                         | Secondary failure mode after Amnesia is fixed.                                         | Even with some state, you can still do unnecessary work.                                                                                        |
| **Failure-Driven Chain**     | An ordered sequence of techniques inside a Super-Family. You move to the next technique only when the assumptions of the current one are violated. | Navigation mechanism within a family.                                                  | Prevents random technique guessing. Forces disciplined escalation.                                                                              |
| **Cross-Family Exit**        | A deliberate hand-off to a different Super-Family when the current family's tools cannot satisfy the constraints.                                  | System integration layer.                                                              | Turns five separate toolboxes into one coherent system.                                                                                         |
| **Monotonicity**             | A property of a sequence or function that is non-decreasing or non-increasing. Once a direction is established, it never reverses.                 | Enables predictable pointer movement, binary decisions, and certain window techniques. | Critical assumption for many Sliding Window, Two Pointer, Binary Search, and greedy solutions. Negatives or arbitrary updates often destroy it. |
| **Invariant**                | A condition that is true before and after every iteration of a loop or recursive call.                                                             | Correctness anchor for pointer and window algorithms.                                  | If the invariant is maintained, the final answer is correct by construction.                                                                    |
| **Space Tax**                | Extra memory paid to recover information that a lower-space technique discarded.                                                                   | Explicit cost of moving from Vise back to Ledger, or from Heap to Segment Tree.        | Always quantify it when escalating.                                                                                                             |
| **Dimensional Collapse**     | Treating a higher-dimensional structure as a sequence of lower-dimensional elements.                                                               | Allows Family 1 tools on matrices.                                                     | Common: process each row as an "element" and run prefix / window on rows.                                                                       |

## 2. Global Diagnostic Dimensions

**Primary Dimension — Topology** (answered first)

| Topology              | Meaning                                                                 | Routes To |
| --------------------- | ----------------------------------------------------------------------- | --------- |
| Line / Stream         | Contiguous or sequential data (arrays, strings, streams)                | Family 1  |
| Ordered Ranges        | Data that is sorted or can be treated as intervals on a line            | Family 2  |
| Node Network          | Explicit or implicit nodes connected by edges (trees, graphs, grids)    | Family 3  |
| Mutable / Streaming   | Data that changes over time or arrives incrementally                    | Family 4  |
| Combinatorial Futures | Problems defined by sequences of choices with exponential possibilities | Family 5  |

**Secondary Dimensions** (used to refine the path inside a family or trigger exits)

- Contiguous vs Discrete
- Sorted / Ordered vs Unordered
- Static vs Dynamic (mutable)
- Weighted vs Unweighted
- Presence of cycles
- Presence of negatives or non-monotonic updates
- Need for one solution vs all solutions vs counting solutions
- Constraint scale — see 04 — Formulas & Heuristics, §2 for the canonical N-scale table

## 3. The Five Super-Families (Core Taxonomy)

### 3.1 Super-Family 1: Linear Array Optimization
**(Sliding Window • Two Pointers • Prefix Sum + Hash Map)**

**Definition**
Techniques that process one-dimensional sequences by maintaining a limited amount of state while scanning, instead of using nested loops.

**Core Conflict**
Exhaustive nested loops produce Algorithmic Amnesia and Computational Redundancy.

**Internal Structure**

- **Frame (Sliding Window)** — Maintains a contiguous segment that satisfies a constraint.
  - Fixed-size: window length is constant.
  - Variable-size: expand with `right`, contract with `left` when invalid.
  - Key assumption: adding/removing elements has predictable effect (often requires non-negative values or monotonicity).

- **Ledger (Prefix Sum + Hash Map)** — Precomputes cumulative information so any range can be evaluated in $O(1)$ after $O(n)$ preprocessing.
  - Position payload: `Map<Value, Index>`
  - Frequency payload: `Map<Sum, Count>`
  - Span payload: `Map<Sum, Earliest Index>`
  - Strength: works with negatives and non-monotonic data.

- **Vise (Two Pointers)** — Uses two indexes that move toward each other or in the same direction under a clear invariant.
  - Converging: opposite ends (requires sorted data).
  - Same-directional: both move left-to-right.
  - Fast & Slow: classic cycle detection or in-place filtering.

**Failure-Driven Chain**
Frame → fails on negatives or loss of monotonicity → Ledger → fails when $O(1)$ extra space is required → Vise → fails when original indices must be recovered → return to Ledger (pay the space tax).

### 3.2 Super-Family 2: Sorted Search & Range Compression
**(Binary Search • Rotated Arrays • Intervals • Sweep Line)**

**Definition**
Techniques that exploit order (existing or imposed) to discard large portions of the search space or to collapse overlapping intervals into a linear pass.

**Core Conflict**
Even when order exists, brute force still examines every element or every possible threshold.

**Internal Structure**

- **Pivot / Binary Search Family**
  - Classic: find exact target or bound in sorted array.
  - Rotated: first locate the rotation pivot, then search the correct half.
  - Binary Search on Answer: the answer itself lies on a monotonic search space; feasibility is checked in $O(n)$ or better.

- **Sweep Line / Interval Collapse** — Convert ranges into start and end events, sort them, and process left-to-right while maintaining active state. Used for merging intervals, coverage problems, meeting rooms, skyline, etc.

**Failure-Driven Chain**
Classic Binary Search → array is rotated → find pivot + search → the search space *is* the answer → Binary Search on Answer. For range problems: sort endpoints → Sweep Line.

### 3.3 Super-Family 3: Hierarchical & Network State
**(Trees • Graphs • Grids • Union-Find)**

**Definition**
Techniques for data organized as nodes and edges, where brute force either explores every path or loops forever on cycles.

**Core Conflict**
Nodes + edges: naive traversal either misses structure or fails to terminate.

**Internal Structure**

- **Stack / Recursion (DFS)** — depth-first order, path recording. Tree DFS, topological sort (DFS).
- **Queue (BFS)** — level-order, shortest path. Tree / Grid / Graph BFS.
- **State Tracker** — cycle prevention, components. Visited set, 3-coloring, Union-Find.

**Failure-Driven Chain**
Pure tree (no cycles) → DFS/BFS with no visited set required → cycles present → Graph/Grid → unweighted shortest path needs BFS + visited, any path/components/cycles needs DFS + coloring, many merges needs Union-Find → weighted edges → exit to Family 4 (Dijkstra) → count-all-paths or heavy constraints → exit to Family 5.

*Full variant matrices: see 05 — Micro-Systems. Complexity formulas: see 04 — Formulas & Heuristics.*

### 3.4 Super-Family 4: Dynamic Priority & Streaming
**(Heaps • Tries • Top-K • Streaming Statistics)**

**Definition**
Techniques for data that is mutable or arrives over time, where full re-sort on every update is too expensive.

**Core Conflict**
Data changes; recomputing full order on every change is wasteful.

**Internal Structure — two orthogonal tracks**

- **Priority / Order-Statistic Track**: Heap (partial order) → Balanced BST / Fenwick / Segment Tree when full sorted order or repeated order-statistic queries are needed.
- **Prefix / String Track**: Trie (shared prefixes collapse) → plain Hash Set when prefix sharing is low or the alphabet is huge.

**Note on usage**
This family is most often *embedded* inside Families 1–3 rather than being the primary topology — e.g. Window + Deque/Heap for sliding window extremes, Graph + Heap for Dijkstra, Sweep + Heap for skyline.

*Full variant matrices: see 05 — Micro-Systems. Complexity formulas: see 04 — Formulas & Heuristics.*

### 3.5 Super-Family 5: Exhaustive State-Space & Optimization
**(Greedy • Backtracking • Dynamic Programming)**

**Definition**
Techniques for problems with multiple future choices, where the naive decision tree is exponential.

**Core Conflict**
Exponential decision tree; must prove a shortcut or compress the state space.

**Internal Structure**

- **Greedy**: locally optimal choice, must be proven correct (exchange argument or matroid).
- **Backtracking**: explore every branch, undo choices (push → recurse → pop), and prune when possible. Suitable when $n$ is small or all solutions are required.
- **Dynamic Programming**: exploit overlapping subproblems and optimal substructure. Can be top-down (memoization) or bottom-up (tabulation). State design is the central difficulty.

**Failure-Driven Chain**
Can I prove a greedy choice property? → Greedy. No → Backtracking. Same subproblems appear many times or $n$ is too large → Dynamic Programming.

## 4. Cross-Family Relationship Ontology

| Source Family | Trigger Condition                                     | Target | Relationship Type              |
| ------------- | ----------------------------------------------------- | ------ | ------------------------------ |
| 1             | Problem is 2-D version of a 1-D pattern               | 1      | Dimensional collapse           |
| 1             | Need current max/min inside a window                  | 4      | Embedding                      |
| 2             | Feasibility check is itself a non-trivial problem     | 1 or 5 | Call-out                       |
| 3             | Edges carry weights                                   | 4      | Algorithmic upgrade (Dijkstra) |
| 3             | Must count paths or handle heavy constraints          | 5      | Exit                           |
| 4             | The primary topology is still a line, graph, or range | 1–3    | Embedding (most common usage)  |
| 5             | Any underlying topology                               | Any    | Can be layered on top          |
